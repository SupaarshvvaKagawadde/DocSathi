# Account recovery and background reminders

Forgot password sends the same response for existing and absent accounts. A configured SMTP transport queues a 30-minute single-use reset link. Opening it lets the applicant choose and confirm a new password. The fragment token is removed from the browser address before submission. Successful reset revokes all sessions and account tokens; originals stay private. Expired, reused and concurrent-reset links fail. Normal password changes also invalidate account links.

Configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` and the existing `APP_ORIGIN` in the server environment. The sender must be accepted by your mail provider. Port 465 uses direct TLS; other ports require STARTTLS, with certificate verification enabled. Production application links require the existing HTTPS deployment configuration. Credentials belong in the private environment, never the repository. Restart the server after configuration. With no mail transport, the UI explains the unavailable delivery service and never claims that an email was sent.

In development without SMTP the server uses the local outbox automatically (or set `MAIL_TRANSPORT=outbox`; `MAIL_TRANSPORT=none` switches email off). Messages are written as private `.eml` files (mode 0600) under `DATA_DIR/outbox`, and the recovery screens say that the link is in the local outbox rather than an inbox. `npm run outbox` lists them, `npm run outbox -- latest` prints the newest one. The outbox refuses to start when `NODE_ENV=production`.

In Settings, request an email verification link, follow it, refresh verification status and enable **Email my enabled reminders**. Deadline and source-change preferences apply to in-app and email reminders. Email is off by default. Demo accounts cannot receive mail. Fresh accounts have no applications, originals, checklists, reports or reminders.

Account emails (reset, verification and guardian approval) are sent as soon as they are queued. A server worker also runs every minute, independent of browser activity. It generates reminders in bounded batches and sends queued mail with a persistent lease, bounded retries and exponential backoff. A browser can be closed; the server and configured SMTP service must remain running. Deadline reminders use Asia/Kolkata and are deduplicated per deadline/bucket. Source notices concern published checklist changes or captured registry updates; this is not continuous remote website surveillance. Unread reminders remain in the app if email delivery fails.

Delivery rechecks verification, opt-in, reminder preferences, archived state, source ownership, retained originals and deadline currency before sending. Mail contains a generic reminder and workspace link, without filenames, application titles, extracted facts or attachments. Delivery already in progress cannot be recalled. SMTP acceptance establishes provider handoff, not inbox arrival. A crash after provider acceptance but before recording delivery may cause a repeated message; SMTP does not provide exactly-once delivery.

The private queue persists retry metadata and fingerprints, never raw reset tokens or email message bodies. Bearer tokens are generated when sending and only their hashes are saved. Failed link delivery discards its token before retrying. Queues, tokens and verification records cascade with account erasure; reminder mail cascades with folder deletion. Encrypted restore preserves unfinished upload chunks but clears sessions, account tokens and reset/verification requests so an older backup cannot revive a consumed account link. The existing deletion ledger still protects erased originals/accounts.

## Notifications on closed browsers

In Notifications, **Turn on notifications** registers the current browser for Web Push. The server signs requests with VAPID (RFC 8292, ES256) and encrypts each message for that browser (RFC 8291, aes128gcm) using Node's built-in crypto; no third-party push library is involved. Keys come from `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT`, or are generated once into `DATA_DIR/vapid.json` (mode 0600). Subscriptions are accepted only for HTTPS endpoints of the browser vendors' push services (Google, Mozilla, Apple, Microsoft), which keeps the server from being pointed at internal addresses.

The same minute worker sends each new, unread deadline or source reminder once per device. Lock-screen text is generic (“An application deadline is coming up. Open DocSathi to see which one.”) and opens the application inside the app; titles, filenames and extracted facts are never sent. **Send a test notification** checks a device. Devices that the push service reports as gone (404/410) are removed at once, others after five consecutive failures. Subscriptions belong to one account and are erased with it. The browser itself must still be installed and able to wake its service worker; a powered-off device receives the notice when it reconnects, subject to the push service's retention.

Validate live delivery using a synthetic test account before deployment: request recovery, check the configured inbox, reset, verify that earlier sessions fail, then verify the address and enable a synthetic deadline reminder with the browser closed. Provider credentials and inbox delivery were not supplied for this development verification; automated tests use an injected transport and do not email real recipients.

## Guardian approval emails

Under-18 registrations send the parent or guardian a 7-day approval link (`#guardian=`) and, after approval, a link to view or withdraw it (`#guardian-manage=`) valid until 30 days after the applicant turns 18. Only token hashes are stored, tied to the current request, so links sent before the applicant changed the guardian's address stop working. The applicant's password changes and resets leave guardian links intact. Restoring a backup clears guardian links like every other account link, so a restored snapshot cannot revive a used approval; the applicant sends the request again from the waiting page, and an approved guardian who needs a new withdrawal link asks support. See [applicant tools](APPLICANT_TOOLS.md).
